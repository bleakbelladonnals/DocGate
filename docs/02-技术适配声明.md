# 技术适配声明

> 对齐文档：`AI产品Vibe Coding通用技术栈手册.md`、`docs/01-产品需求文档-DocGate-MVP.md`  
> 适用阶段：第 1 阶段 MVP

## 1. 产品形态判断

- 产品类型与核心任务：本地开发者工具/文档验收中间件；把批注意见、Agent 回执和真实 Markdown Diff 变成可逐任务验收的证据链。
- 核心交互：分阶段人工确认。批注由上游工具完成，人工验收是产品核心而非展示壳。
- 开发路径：纵向切片。第一阶段同时实现最小 CLI、核心领域逻辑、受控本地 API 和最小正式 Web 验收页。
- 当前阶段范围：单用户、单工作区、单 Markdown 文件的完整一轮验收与返工闭环。

## 2. 采用的默认方案

- Python 3.11.x：作为核心与本地 API 语言，遵循手册默认后端基线。
- FastAPI：提供只监听 loopback 的受控 `/api/v1` 接口，并承载会话/验收能力。
- Pydantic：校验批注适配结果、任务、回执、证据、决策和错误结构。
- pytest：覆盖领域逻辑、状态机、异常路径、持久化恢复和 API 集成。
- Next.js + TypeScript + App Router + Tailwind CSS：人工验收是核心交互，按正式 Web 纵向切片实现，不做一次性静态调试页。
- npm + 锁文件：遵循 Web 默认依赖管理；不混用 pnpm/yarn。
- Git：项目初始化后用于代码恢复与审查；不得覆盖用户已有文档。
- `/api/v1`：新建 API 使用版本前缀；CLI 可直接调用同一领域服务，不复制业务规则。
- 确定性代码状态机：会话推进、接受条件和返工范围由代码控制，不交给模型决策。

## 3. 触发的按需模块

- Plannotator CLI 适配器：由“复用现有批注能力”触发；作为外部进程/JSON 边界接入，不复制其 UI 和内部模型。
- 本地结构化文件持久化：由单用户、低并发、资产文件为主触发；使用带 `schemaVersion` 的 JSON/Markdown 文件、原子替换和会话锁。
- Markdown 解析器：由标题路径、front matter 和结构有效性检查触发；开工时锁定一个 Python 库并记录版本。
- 本地文件 Diff：由证据生成触发；P0 使用确定性行级算法，算法封装在领域层，便于 P1 替换或补充 AST Diff。
- 最小浏览器 E2E 工具：由核心验收交互触发；优先使用 Playwright，覆盖任务决策、刷新恢复和返工生成。

## 4. 偏离或暂缓的默认方案

- 暂缓 SQLite + SQLAlchemy + Alembic：P0 无账号、跨文档查询、复杂事务或多人并发；文件会话更便于检查和携带。出现多用户、复杂筛选、跨会话统计或并发写入时重新评估数据库。
- 暂缓模型 SDK 与真实模型冒烟：P0 不调用模型，只约定 Agent 交换协议；因此手册的模型双层验收在本阶段“不适用”，不得伪造真实模型测试。P1 启用语义验证器时再补充模型配置、超时、有限重试、结构校验和真实冒烟。
- 暂缓 SSE/任务队列：P0 单文件 Diff 与验证目标应在普通请求内完成；若 2 MiB 文件验证在目标机器上超过 3 秒，则改为“提交任务 + 查询状态”，不得无限延长 HTTP 请求。
- 不采用早先讨论的 Node.js 核心 CLI：Plannotator 通过进程和 JSON 协议隔离，不要求与核心同语言；采用手册默认 Python 可减少无必要偏离。前端仍使用 TypeScript。
- 暂缓桌面壳：P0 由 CLI 启动 loopback API 和浏览器；验证重复使用价值后再评估 Tauri/Electron。

## 5. 强制底线检查

- 密钥与隐私：计划通过。P0 无模型 Key；`.env` 仍加入 `.gitignore`，只提交 `.env.example`。日志不记录文档或批注全文。
- 数据与任务可恢复：计划通过。所有关键状态持久化到带版本的会话目录；基线不可变；原子写入；单会话锁；损坏文件进入可诊断错误状态。
- 输入输出校验：计划通过。API、外部 CLI JSON、回执和持久化数据均经过 Pydantic；路径限制在工作区内。
- 错误与日志边界：计划通过。统一 `{"error":{"code","message","details?"}}`，用户响应不返回堆栈；内部日志使用错误类型和 request/session ID。
- 测试与真实验收：pytest + API 集成 + 前端类型/代码检查 + Playwright + 三份真实 Markdown 人工验收。P0 无模型调用，因此无真实模型冒烟。
- 人工确认可恢复：计划通过。任务决策和未声明修改决策每次提交后持久化，刷新和重启可继续。

## 6. 环境自检快照

- 当前目录不是 Git 仓库；正式开工时应在确认目录后初始化，不覆盖现有文件。
- 系统 `python3` 当前报告为 Python 3.9.6，不满足新项目默认 Python 3.11.x；开工时需发现可用 3.11 解释器或给出安装指引，再创建 `.venv`。
- 检测到 Node 可执行路径，但版本检查未得到可靠结果；开工时需验证 Node.js 22 LTS 与 npm，异常时先给出可执行修复指引。
- 当前仓库只有文档，没有已有应用代码、依赖、测试和数据迁移负担。
- 当前未要求或提供模型 API Key，且 P0 不需要。

## 7. 需要产品经理决定的问题

无。以下采用暂定默认值，不阻塞第一阶段：产品名 DocGate、macOS 优先、本地单用户、2 MiB 文件上限、P0 不启用模型语义验证。

## 8. 对产品经理的确认摘要

- 没有新增云服务、模型调用费用或数据上传。
- 第一阶段新增一个本地 Web 验收页，因为逐任务接受/返工是核心价值。
- 数据库存储、桌面应用、团队协作和语义模型验证均被暂缓，不影响本阶段验收。
