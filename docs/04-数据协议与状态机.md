# DocGate 数据协议与状态机｜v1

> 本文是第 1 阶段的领域契约。实现可增加内部字段，但不得改变这里定义的语义或绕过状态约束。所有 JSON 使用 UTF-8、`snake_case` 和显式 `schema_version`。

## 1. 通用约定

- 时间：UTC ISO 8601，例如 `2026-08-20T08:30:00Z`。
- hash：小写 SHA-256 十六进制字符串，hash 对象必须明确是字节内容还是规范化 JSON。
- ID：随机、不可由数组下标推导；前缀分别为 `ses_`、`rnd_`、`tsk_`、`hnk_`、`dec_`。
- 路径：协议只保存相对 `workspace_root` 的 POSIX 形式路径；API 不返回绝对路径。
- 枚举：未知值不得静默映射；兼容策略由 `schema_version` 决定。
- 原文：任务证据可以保存必要的 quote/prefix/suffix，但日志和错误不得记录这些字段。

## 2. 会话与轮次

一个 Session 对应一个源 Markdown 文件的一次完整审阅目标；一个 Round 对应 Agent 的一次修改与验收尝试。返工会创建新 Round，历史 Round 不可覆盖。

```json
{
  "schema_version": 1,
  "session_id": "ses_01k...",
  "source_path": "docs/example.md",
  "initial_source_hash": "sha256...",
  "state": "human_review",
  "active_round_id": "rnd_0001",
  "created_at": "2026-08-20T08:30:00Z",
  "updated_at": "2026-08-20T08:42:00Z"
}
```

Session 状态：

| 状态 | 含义 | 合法后继 |
| --- | --- | --- |
| `baselined` | 初始快照已保存 | `feedback_ready` |
| `feedback_ready` | 任务与返工包已生成 | `agent_working` |
| `agent_working` | 等待外部 Agent 修改/回执 | `result_submitted` |
| `result_submitted` | 回执与结果快照已保存 | `verifying` |
| `verifying` | 正在生成证据 | `human_review` 或失败后回 `result_submitted` |
| `human_review` | 等待逐项人工决策 | `accepted` 或 `rework` |
| `rework` | 返工包已生成 | `agent_working`（创建新 Round） |
| `accepted` | 会话已接受，终态 | 无 |

规则：

- 后端是唯一状态转换执行者；前端不得提交任意目标状态。
- 重复调用已完成动作必须幂等，或返回明确 `INVALID_STATE_TRANSITION`。
- `accepted` 后不可写；若需继续审阅，以接受结果创建新 Session。
- `verifying` 进程中断时，重启后可以从已有回执/结果快照重新运行，不依赖内存。

轮次元数据：

```json
{
  "schema_version": 1,
  "round_id": "rnd_0001",
  "number": 1,
  "base_hash": "sha256...",
  "result_hash": "sha256...",
  "created_at": "2026-08-20T08:35:00Z",
  "submitted_at": "2026-08-20T08:40:00Z"
}
```

第 1 轮 base 是初始基线。返工轮次 base 是上一轮 `result.md` 的不可变副本；已接受任务进入 protected 列表，未通过任务继续活跃。

## 3. Change Task

任务包：

```json
{
  "schema_version": 1,
  "session_id": "ses_01k...",
  "base_hash": "sha256...",
  "tasks": []
}
```

单个任务：

```json
{
  "task_id": "tsk_01k...",
  "instruction": "把这段结论改得更具体，并补充可验证指标。",
  "annotation_source": {
    "adapter": "plannotator",
    "external_id": "comment-7",
    "raw_type": "text_selection"
  },
  "locator": {
    "exact_quote": "当前方案能够显著提升效率。",
    "prefix": "试点结果显示，",
    "suffix": "因此建议进入下一阶段。",
    "occurrence": 1,
    "start_line": 42,
    "end_line": 42,
    "heading_path": ["验证结果", "效率"],
    "locator_status": "unique"
  },
  "scope": {
    "allowed": "优先修改锚点段落；为补充指标可修改同一小节。",
    "forbidden": "不得改动其他章节、front matter 或已接受任务。"
  },
  "created_at": "2026-08-20T08:35:00Z"
}
```

字段规则：

- `instruction` 不能为空，保留人的原始意图，不由模型改写。
- `exact_quote` 必须来自该轮 base；导入时验证。
- `occurrence` 从 1 开始，解决相同文本重复出现；仍无法唯一解析时为 `null` 并标记 ambiguous。
- `start_line/end_line` 是该轮 base 的 1-based 行号，只作为一项证据，不能单独充当永久锚点。
- `heading_path` 由确定性 Markdown 解析生成，解析失败时可为空并产生检查告警。
- `locator_status`：`unique | ambiguous | missing`。后两者不得自动得到高置信归因。

## 4. Agent Brief

`agent-brief.md` 是确定性生成物，至少包含：

```markdown
# DocGate Change Request

- Session: ses_...
- Round: rnd_...
- Target: docs/example.md
- Base SHA-256: ...
- Receipt path: .docgate/.../receipt.json

## Task tsk_...

Instruction: ...
Anchor: ...
Allowed scope: ...
Forbidden: ...

## Completion contract

1. Edit the target file; a text response alone is not completion.
2. Return one outcome per task.
3. Do not claim changes that are absent from the target file.
4. Use clarification or blocked instead of guessing.
5. Write a receipt matching receipt.schema.json.
```

返工 Brief 还必须列出上一轮已接受的 task ID 和 protected 区域，要求不回退。

## 5. Agent Receipt

回执是“不可信声明”，只能通过 schema 校验，不能直接证明完成。

```json
{
  "schema_version": 1,
  "session_id": "ses_01k...",
  "round_id": "rnd_0001",
  "base_hash": "sha256...",
  "result_hash": "sha256...",
  "agent": {
    "name": "codex",
    "version": null
  },
  "tasks": [
    {
      "task_id": "tsk_01k...",
      "outcome": "addressed",
      "summary": "加入了 30% 节省时间和三份样本文档的验证门槛。",
      "claimed_changes": [
        {
          "path": "docs/example.md",
          "start_line": 42,
          "end_line": 45
        }
      ],
      "notes": null
    }
  ],
  "submitted_at": "2026-08-20T08:40:00Z"
}
```

`outcome`：

- `addressed`：声称已完成；
- `partial`：只完成一部分，`notes` 必须解释剩余部分；
- `clarification`：需要人补充信息，`notes` 必填；
- `blocked`：受工具/文件/权限约束无法完成，`notes` 必填；
- `not_applicable`：认为意见不适用，`notes` 必填，仍需人工决策。

校验规则：

- 必须覆盖当前返工包内每个活跃 task，且每个恰好一次；
- 不得包含其他 Session/Round 的 task；
- `base_hash` 必须等于该轮 base；
- `result_hash` 必须等于提交时源文件字节 hash；
- `addressed` 的 `claimed_changes` 不能为空；其他 outcome 可以为空；
- claimed line 只是一项声明，越界或不存在即产生失败检查。

## 6. Diff Hunk

```json
{
  "hunk_id": "hnk_01k...",
  "old_start": 40,
  "old_lines": 4,
  "new_start": 40,
  "new_lines": 7,
  "before": "...",
  "after": "...",
  "associated_tasks": [
    {
      "task_id": "tsk_01k...",
      "confidence": "certain",
      "methods": ["base_range_overlap", "unique_quote"],
      "reasons": ["hunk 与唯一锚点的 base 行 42 重叠"]
    }
  ],
  "unattributed": false
}
```

`confidence`：`certain | likely | weak`。

P0 归因规则按优先级执行：

1. hunk 的旧文件区间与 unique locator 的 base 行区间重叠：`certain`。
2. 纯插入紧邻 unique locator，或位于同一 heading 且距离不超过 3 行：`likely`。
3. 只有 Agent claimed line 支持，缺少客观锚点支持：`weak`。
4. `ambiguous/missing` locator 不得仅凭文本相同得到 `certain`。
5. 同一 hunk 可关联多任务；同一任务可关联多 hunk。
6. 只有 `weak` 关联的 hunk 仍进入未声明修改区，同时可展示“疑似与任务相关”。

不得只输出不可解释的相似度分数。若内部计算分数，界面仍必须展示规则、证据和不确定性。

## 7. Verification Evidence

机器检查：

```json
{
  "schema_version": 1,
  "session_id": "ses_01k...",
  "round_id": "rnd_0001",
  "checks": [
    {
      "rule_id": "DG-HASH-001",
      "subject_type": "round",
      "subject_id": "rnd_0001",
      "status": "pass",
      "message": "回执结果 hash 与结果快照一致。",
      "evidence": {"actual_hash": "sha256..."}
    }
  ],
  "generated_at": "2026-08-20T08:41:00Z"
}
```

`status`：`pass | warning | fail | uncertain`。P0 规则集：

| Rule ID | 检查 | 失败/告警 |
| --- | --- | --- |
| `DG-HASH-001` | receipt base hash 等于轮次 base | fail |
| `DG-HASH-002` | receipt result hash 等于结果快照 | fail |
| `DG-DIFF-001` | 结果相对 base 存在真实变化 | fail（若任何任务 addressed） |
| `DG-TASK-001` | 每个活跃任务有且仅有一个回执项 | fail |
| `DG-TASK-002` | addressed 任务至少有 certain/likely hunk | fail 或 uncertain（锚点歧义时） |
| `DG-CLAIM-001` | claimed range 存在并触达真实 hunk | fail |
| `DG-LOC-001` | locator 在 base 中可唯一解析 | warning/uncertain |
| `DG-MD-001` | Markdown 解析未出现阻断错误 | fail |
| `DG-FM-001` | 原有 front matter 仍可解析 | fail |
| `DG-SCOPE-001` | 存在未归因 hunk | warning，要求人工决定 |
| `DG-BASE-001` | 提交/验证期间源文件未漂移 | fail |

规则结果不能将 `verification_status` 自动映射成人工接受。

## 8. 三个正交状态

每个任务分别记录：

```json
{
  "task_id": "tsk_...",
  "agent_status": "addressed",
  "verification_status": "warning",
  "human_status": "rework_requested"
}
```

- `agent_status`：`pending | addressed | partial | clarification | blocked | not_applicable`。
- `verification_status`：`not_checked | pass | warning | fail | uncertain`。
- `human_status`：`pending | accepted | rework_requested | clarification_requested`。

UI 必须分别展示，不得合并成一个模糊的“完成/未完成”。

## 9. Human Decision

任务决策：

```json
{
  "decision_id": "dec_01k...",
  "subject_type": "task",
  "subject_id": "tsk_01k...",
  "decision": "rework_requested",
  "reason": "指标有了，但缺少测量口径。",
  "decided_at": "2026-08-20T08:45:00Z"
}
```

未声明修改决策的 `subject_type` 为 `hunk`，`decision` 为 `accepted | revert_requested`。所有决策支持覆盖更新，但必须保留 `updated_at`；P0 可不做完整审计历史，最终 Round 快照必须保留最终决定。

## 10. 接受与返工门槛

接受会话需要同时满足：

- 所有活跃 task 的 `human_status=accepted`；
- 所有 unattributed/weak-only hunk 均有 `accepted` 决策；
- `DG-HASH-001`、`DG-HASH-002`、`DG-MD-001`、`DG-FM-001`、`DG-BASE-001` 无 fail；
- 源文件当前 hash 仍等于本轮 `result_hash`。

返工包包含：

- `rework_requested` 和 `clarification_requested` 的任务；
- `revert_requested` 的未声明 hunk；
- 上一轮已接受任务与区域的 protected 摘要；
- 新轮次 base/result 约束和回执 schema。

## 11. 本地目录与原子性

推荐结构：

```text
.docgate/sessions/{session_id}/
├── session.json
├── tasks.json
└── rounds/
    ├── 0001/
    │   ├── round.json
    │   ├── baseline.md
    │   ├── annotations.raw.json
    │   ├── agent-brief.md
    │   ├── receipt.schema.json
    │   ├── receipt.json
    │   ├── result.md
    │   ├── diff.json
    │   ├── evidence.json
    │   ├── decisions.json
    │   └── rework-brief.md
    └── 0002/
        └── ...
```

写入过程：校验 → 写同目录临时文件 → flush → fsync → 原子 rename → 更新索引。失败时保留上一份有效文件。不得先 truncate 正式文件再写入。
