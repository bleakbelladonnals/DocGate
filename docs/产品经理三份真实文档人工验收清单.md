# 产品经理下一步只需做什么｜三份真实文档人工验收

> 工程自动化和真实 Plannotator 冒烟已经完成；本清单验证“真实长文档是否真的减少全文重读”。请由产品经理亲自完成，结果不能由自动化或开发者代填。

## 开始前

- [ ] 另建一个私有验收文件夹，不要直接修改仓库原文。
- [ ] 把以下三份文档各复制一份到该文件夹；每份确认 3,000 字以上：
  1. `AI文档处理中间件PRD.md`；
  2. `AI产品Vibe Coding通用技术栈手册.md`；
  3. 一份你日常真实使用、可安全交给本地 Agent 的 3,000 字以上 Markdown。
- [ ] 在仓库根目录完成 README 的安装步骤，并把 `DOCGATE_WORKSPACE_ROOT` 设置为这个私有验收文件夹。
- [ ] 启动 API 和验收页，浏览器打开 `http://127.0.0.1:3000/sessions`。

## 每份文档都重复一次

- [ ] 记下开始时间。
- [ ] 运行 `docgate review <相对路径.md>`，确认打开的是 Plannotator v0.24.2。
- [ ] 至少创建 5 条意见，五种类型各一条：局部改写、补充可验证指标、删除内容、一个意见要求跨两处修改、需要 Agent 澄清。
- [ ] 点击 Plannotator 的 **Send Feedback**。
- [ ] 打开该会话的 `agent-brief.md`，确认五条意见、选中文本和上下文都能认出，没有串到相同文本的错误位置。
- [ ] 把 brief 和 `receipt.schema.json` 交给你实际使用的外部 Agent；要求它修改源文件并写 `receipt.json`。
- [ ] 提交回执并运行 verify。另加一处与任何意见无关的小改动，确认它进入“未声明修改”。
- [ ] 打开验收页，不先读全文；只看任务卡完成五条任务和未声明修改的决定。
- [ ] 至少把一条任务标为“要求返工”或“需要澄清”，生成返工包；确认其中只有未通过项，并列出受保护的已接受项。
- [ ] 让 Agent 完成返工并提交下一轮回执；确认旧 Round 仍可查看。
- [ ] 在所有任务、未声明修改和阻断检查处理完后接受会话。
- [ ] 刷新页面并重启 API，确认决定和 accepted 状态仍在。
- [ ] 记下结束时间；最后才决定是否仍需要全文重读，并写明原因。

```markdown
- 发现的遗漏/误改数量：
- 与手工全文复核相比的主观时间变化：
- 刷新/重启恢复：通过/不通过；现象：
- 阻塞问题：
- 结论：通过 / 返工 / 不通过
```

## 三份完成后的产品结论

- [ ] 三份文档的批注都形成稳定任务，所有真实 hunk 都有关联或进入未声明修改。
- [ ] 所有“Agent 声称完成但没有对应变化”的情况都被任务卡暴露。
- [ ] 至少两份文档可以不阅读全文完成决定；若不能，写明缺失的证据。
- [ ] 计算三次验收用时，与原来的“全文重读 + 手工 Diff”比较是否下降至少 30%。
- [ ] 只基于真实记录决定：通过第 1 阶段人工验收 / 继续返工 / 产品方向需要收缩。

不要把 `.docgate/`、真实回执、私人文档或验收过程日志提交到 Git；只提交不含原文和隐私的结论摘要。
