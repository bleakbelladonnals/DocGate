01 · Executive read

有强邻居，但核心“验收断层”仍未被占满

市场已经快速验证了 AI 计划/文档的可视化批注需求；竞争正在从“给 Agent 留评论”转向“让人控制 Agent 的修改闭环”。DocGate 不该再做一个批注器，而应成为批注器之后的证据与决策层。

最强入口
Plannotator

覆盖计划、Markdown、HTML、代码 Diff 与主流 Agent；分发和使用面最强，也是 DocGate 当前上游。

最近体验
Redline

本地 Markdown、内联评论、Agent 对话、修订历史与修订后内联 Diff，已逼近完整文档闭环。

最强流程
MD Feedback

结构化批注、MCP、质量门槛、逐项批准/拒绝和 before/after，控制模型最接近。

DocGate 空位
3-way

人的任务、Agent 不可信回执、磁盘真实 Diff 三方对账，再加未声明修改与返工范围收敛。

关键判断：DocGate 的直接对手不是 Word，而是“Agent Review Loop”工具

Word、Draftable、GitHub PR 和 Filestage 已经教育用户如何看变更、给意见和批准；新一代产品则把这些机制接入本地 Agent。DocGate 需要占据“Agent 说做完之后，如何证明并验收”的位置。

Verify
before trust.

调研边界：“未发现”指本次查阅的公开官网、官方文档和 README 未展示该能力，不代表产品内部绝对不存在。GitHub Stars 只作开发者注意力快照，不等同于用户量或收入。

02 · Product model

项目本质：本地 AI 文档的修改验收门

基于仓库 README、MVP PRD、协议和当前前端实现，DocGate 的 P0 不是格式转换、协作发布或自动语义裁决，而是单用户、单工作区、单 Markdown 文件的一轮可靠验收与返工闭环。

不可变基线目标 Markdown、SHA-256、工作区路径与 Round 快照。
稳定任务批注保留 exact quote、prefix/suffix、行号、heading path 与 task_id。
Agent 执行任意 Agent 修改原文件，同时提交结构化 receipt；声明默认不可信。
证据对账真实行级 Diff、task↔hunk 多对多归因、确定性规则、未声明修改。
人工决策逐任务接受 / 返工 / 澄清；只把未通过项送入下一轮。
授权来源

人的批注

说明“允许改什么”，原文和定位证据必须保留。

解释线索

Agent 回执

说明“它声称做了什么”，不能直接使任务通过。

客观事实

真实文件 Diff

说明“磁盘实际发生了什么”，但开放式语义仍由人判断。

03 · Direct competitors

10 个直接 / 近直接竞品

筛选标准：目标用户包含 AI Agent 使用者，且至少覆盖“Markdown/计划审阅、结构化反馈、Agent 回流、修改后复核”中的三项。按对当前 DocGate MVP 的威胁度排序。

01

Plannotator

威胁 9.2/10Apache-2.07,906 ★

本地浏览器审阅面，覆盖计划、规格、Markdown、HTML、代码 Diff 与 PR；通过 hooks/commands 接入 Claude Code、Codex、Gemini CLI 等，批准后继续，拒绝后把结构化反馈返回 Agent，并展示计划修订 Diff。

最重叠
批注、Agent 回流、批准/拒绝、历史、本地隐私、修改前后审阅。
公开资料未见
Agent receipt 与真实文件的三方核验；任务↔hunk 归因；未声明修改收件箱；逐任务返工门槛。
对 DocGate
竞合关系。继续作为批注上游，但适配层必须可替换；不能把差异化押在批注 UI。
02

Redline

威胁 8.8/10MIT3 ★ · 新项目

面向 AI 文档的本地 Markdown 内联审阅：选区评论、与 Claude/Codex 在线程中讨论、resolve 后让 Agent 改回磁盘；每轮修订前留历史快照，修订后以内联块级/词级 Diff 展示，最后“Looks good”。

最重叠
目标用户、源文件、本地优先、锚定评论、Agent 修订、版本快照、修订后 Diff 几乎一致。
公开资料未见
不可信回执、hash/stale baseline、任务归因置信度、未授权变更隔离、逐条最终决定。
对 DocGate
最危险的产品体验对手。DocGate 必须让“证据卡验收”明显优于它的“阅读全文看红线”。
03

MD Feedback

威胁 8.4/10SUL-1.0 源码可见5 ★

VS Code + MCP 的 Markdown 计划审阅。Fix / Question / Highlight 以内嵌 HTML comment 保存；Agent 可通过 27 个 MCP tools 读取、应用、标记完成；支持质量门槛、Approve / Reject、外部文件 Diff 和 inline before/after。

最重叠
稳定批注、逐项状态、MCP、修改前后、人工批准、门槛和跨会话 handoff。
核心差别
其 gate 主要基于批注解决状态；DocGate 用独立磁盘证据验证 Agent 声明，并暴露未声明 hunk。
对 DocGate
最危险的流程对手。要持续验证其 gate 是否向 hash、归因和未授权变更演进。
04

md-redline

威胁 7.1/10MIT33 ★

Markdown 规格/提示词/设计文档的内联评论工具。评论作为不可见 HTML marker 直接写入 .md；内置 MCP 支持 Agent 主动请求审阅并等待，也支持 Agent 给人的文档留下锚定问题。

最重叠
本地 Markdown、锚点、双向 Agent 审阅、无需复制粘贴、文档仍是事实源。
短板
更偏批注通道；公开首页未呈现修改证据、任务归因、验收门槛与只返工失败项。
对 DocGate
可作为 Plannotator 之外的潜在批注适配器；其“Agent 发起并等待”值得吸收。
05

revdiff

威胁 6.6/10MIT793 ★

用于 Diff、文件和文档的终端 UI，可做行内批注并向 stdout 输出结构化结果，便于直接管道给 Agent；支持全文件 Diff、词级变化、折叠最终视图、Markdown 目录与多 VCS。

最重叠
本地、轻量、真实 Diff、结构化批注、Agent 管道、文档与代码通吃。
短板
没有面向“批注任务是否被完成”的证据模型和状态机，主要是高效看 Diff。
对 DocGate
构成“用户其实只要普通 Diff”的强反证；DocGate 必须量化逐任务聚合比 TUI 节约多少复核时间。
06

Commentary

威胁 6.2/10MIT3 ★

VS Code / Cursor / Windsurf 中对渲染 Markdown 做 Google Docs 式非破坏评论，随后把评论直接 pipe 给 Claude Code、Cursor Agent、Codex 或 Gemini 自动修改文件。

最重叠
渲染态选区评论、多 Agent、原文件不被评论污染、修改直接落盘。
短板
官方建议最终用 git diff 检查；评论仍留在侧栏，不提供独立验收证据和接受门槛。
对 DocGate
证明“批注→Agent”已经组件化；DocGate 应承接其修改后的核验阶段。
07

Annotative

威胁 5.9/10MIT19 ★

VS Code 的持久化 AI review artifacts：可审计划、AI 回复和本地 Git Diff；在 section、block、file、hunk 上留下结构化风险/问题/缺失步骤，保存到项目内 .annotative 并导出 AI-ready prompt。

最重叠
本地持久化、结构化 review artifact、hunk 级评论、open/resolved 状态和导出历史。
短板
关注“如何整理反馈”，不是“如何证明每条反馈被正确执行”。
对 DocGate
其项目内可审计 JSON 和多 review 类型可作为协议/扩展设计参考。
08

PreApp

威胁 5.7/10托管服务 + MIT 集成层1 ★

把 Agent 生成的 Markdown/HTML 发布为稳定链接，收集精确反馈，负责人整理 Revision Brief，Agent 按 ID 拉取并发布 v2；公开协议强调反馈不可信和“两阶段授权”。

最重叠
稳定反馈 ID、locator、Brief、人工授权、版本追溯、Agent 回流与提示注入防护。
核心差别
它解决外部分享/审阅/发布；DocGate 解决本地文件实际执行结果的可信验收。
对 DocGate
若未来做团队/分享，会变为高威胁；P0 阶段更适合作为潜在上下游。
09

pocketspec

威胁 4.4/10MIT1 ★

让用户在手机上阅读 AI 生成的文档/规格，点击段落评论；评论落到 .comments sidecar，Agent 再读取并修订。局域网零配置，锚点失效时降级为 general comment 而不丢数据。

最重叠
Markdown、Agent skill、锚定反馈、本地数据、source of truth 不搬家。
短板
移动阅读/评论通道，不提供执行回执、Diff 归因或验收状态机。
对 DocGate
“离开电脑也能批注”的切入很轻；DocGate 移动端可只做验收卡，不必复制桌面长文。
10

lavish-axi

威胁 4.1/10MIT2,892 ★

本地审阅 Agent 生成的交互 HTML：精确元素/文本批注、Mermaid 白板编辑、反馈队列、Agent long-poll；内置布局诊断收件箱，问题只有在新 revision 同 viewport 复检通过后才算 resolved。

最重叠
本地 Agent 闭环、精确 target、问题 inbox、重新验证、未修复/复发/无法验证状态。
核心差别
对象是 HTML 视觉与布局，不是 Markdown 修改任务和文件语义证据。
对 DocGate
其“不能凭 Agent 说修好，必须下一版本复检”的状态设计与 DocGate 高度同构。

05 · Indirect competitors

23 个间接竞品与机制替代

它们可能抢走预算、替代一个关键步骤，或已经在别的行业把“专业制品转成普通人可读、可批、可批准的表面”做成熟。每组都标出 DocGate 真正应该借的东西。

A · 代码变更审查

把不可读 patch 变成有门槛的决策界面

这是 DocGate 最接近的成熟范式：base/head、hunk、inline comment、request changes、required approval、重新提交后保留上下文。

GitHub Pull Request Reviews闭源 SaaS逐行评论、Approve / Comment / Request changes、分支保护与 required review。借鉴：决策语言和“未满足门槛不能合并”。
GitLab Merge Request Approvals开放核心 + 商业审批规则、指定审批者、推送新 commit 后重置审批。借鉴：新事实出现时旧批准失效，避免 stale acceptance。
Reviewable闭源 SaaS智能行映射避免 rebase 后重审，Flexible Mergeability 控制合并。借鉴：跨版本保留“已看过”状态，减少重复阅读。
CorgReview闭源本地工具把 GitHub PR 式本地 Diff、blocker/question/suggestion 和结构化 Markdown 反馈接给 Agent。借鉴：Agent 完成任务后自动触发自审。
pair-reviewApache-2.0 · 52 ★本地 GitHub 风格 AI 代码审查，人工可采纳/编辑/丢弃 AI 建议。借鉴：把 AI 分析降级为辅助提示，不替代人的结论。
B · 文档红线与比较

把专业文件差异压缩成可导航的变化清单

这组会抢“我只是想看两版差异”的用户；同时证明变化摘要、过滤和视觉层次本身能显著降低复核成本。

Microsoft Word Track Changes / Compare商业软件接受/拒绝单项或全部修改、评论、作者归属与修订视图。借鉴：改变的“状态”必须与改变本身同屏。
Draftable闭源 SaaS / 企业Word/PDF/PPT/TXT/Excel 的 side-by-side、redline、变化列表和同步滚动。借鉴：按变化类型过滤和点击变化直达位置。
Adobe Acrobat Compare商业软件PDF 视觉对比，可按文本、图像、页眉页脚、格式过滤，自动生成变化数量摘要。借鉴：首页先给风险摘要，再让用户下钻。
C · 创意校对与批准

把分散反馈变成明确的版本和审批队列

设计、视频、包装与营销团队早已为“反复看、反复改、意见散落”付费。它们争夺的是同一笔复核时间成本。

Filestage闭源 SaaS跨文件类型的 annotation、review/approval workflow、版本与自动化，并用 Review Agents 按品牌/法规即时检查。借鉴：规则检查应可解释且独立于人工批准。
Ziflow闭源 SaaS在线 proofing 将创意内容、批注、版本和审批集中。借鉴：每个 round 要有明确 owner、截止状态和版本边界。
Frame.io Review & Approval闭源 SaaS视频/创意的 frame-accurate comment、版本和审批。借鉴：文档 locator 应像 timecode 一样稳定、可复现、可在新版本迁移但不能偷换。
D · AI 输出评测

把海量运行轨迹分发给人做结构化判断

对象从“文档”换成“模型运行”，但同样需要采样、排队、标签、多人一致性和人工最终判断。

LangSmith Annotation Queues闭源 SaaS单运行/成对运行排队、reviewer reservation、阈值、评论和 requeue。借鉴：高风险任务优先、uncertain 进入专门队列、需要时重新排队。
LangSmith Inline Trace Annotation闭源 SaaS不仅评价根运行，还能对中间 span 留分数、标签和注释。借鉴：任务证据应允许下钻到规则、hunk 和 locator，而不是只给一个总分。
E · 高风险执行审批

先展示计划，再由人决定是否执行

基础设施领域把“声明要做什么”和“实际应用什么”分为两个阶段，并用 stale plan、policy 和 approval 保护高成本变更。

Terraform plan / apply源码可用 + 商业plan 先生成变更预览，apply 再执行；保存的 plan 让审批对象固定。借鉴：DocGate 的 baseline + result 快照就是文档世界的 plan/apply 边界。
AtlantisApache-2.0把 Terraform plan 放进 PR，通过评论命令和审批后 apply。借鉴：机器执行必须绑定被人看过的具体版本，过期就拒绝。
F · 专业格式转换

把机器/行业格式变成可读、可复用的中间形态

这组不是验收产品，但会决定 DocGate 将来是否扩展到 Word/PDF/科研文档，以及应复用什么而不是重造什么。

PandocGPL-2.0+ · 45,943 ★通用 markup converter，支持 docx、JATS、DocBook、Markdown 等。借鉴：格式转换做成 adapter；canonical source 和审阅证据不要绑定渲染器。
Quarto开源 · 5,947 ★基于 Pandoc 的科研/技术发布系统，把代码、结果、引用、交叉引用转成网站、书和报告。借鉴：专业语义要保留结构 ID，而不只是纯文本。
Microsoft MarkItDownMIT · 174,717 ★把 PDF、Office、图片、音频、HTML 等转成保留结构的 Markdown，主要供 LLM 消费。借鉴：可做未来输入归一化，但不能承诺人类高保真 round-trip。
DoclingMIT · 65,236 ★把复杂文档解析成适合 GenAI 的结构化表示。借鉴：PDF/Office 扩展应将“解析置信度”显式带入任务证据。
MinerU开源 · 77,998 ★复杂 PDF/Office 到 LLM-ready Markdown/JSON。借鉴：专业格式→可读中间态已经高度商品化，DocGate 的价值仍应在变更控制和验收。
G · AI 制品呈现与编辑

减少“AI 输出不好看、分享难、局部改很贵”

这组替代的是生成→阅读→反馈的前半程。它们增长快，却也证明“转换/渲染”本身难成为 DocGate 壁垒。

html-anythingApache-2.0 · 8,349 ★Agentic HTML editor，覆盖报告、演示、海报、社媒卡片等输出面。借鉴：让 Agent 负责丰富呈现，但将展示层视为可重建产物。
MarkraAGPL-3.0 · 757 ★本地优先 AI 原生 WYSIWYG Markdown 编辑器。借鉴：不要和成熟编辑器争编辑体验，提供可被它们调用的验收协议。
即页 jpageMIT · 174 ★HTML/Markdown 秒级预览分享、稳定短链、版本、回滚、权限和 MCP。借鉴：未来分享是独立产品面，不要塞进 P0 本地验收。

07 · Strategic moves

建议：把“验收证据层”做窄、做硬、做成协议

短期不应追逐富文本、分享、团队协作和多格式。最值得投入的是别人公开产品中还没有形成统一心智、但一旦做成就可横向适配多种批注器与 Agent 的证据闭环。

对外定位改成“AI 文档修改验收”

“中间件”是技术形态，不是用户价值。首页第一屏直接展示：Agent 说完成 ≠ 真实完成；DocGate 逐条证明、只返工失败项。

把 Plannotator 定义为上游，不做替身

公开 adapter interface 和 tasks/receipt/evidence schema；优先再接一个 md-redline/Commentary 风格输入，证明核心不依赖单一批注器。

把“未声明修改”做成招牌功能

在演示里故意注入 Agent 顺手重写、改错同名段落、声称完成但无变化、会话外改文件；这是与所有批注工具最容易一眼看懂的差异。

任务卡先回答结论，再展开证据

借鉴 PR / Acrobat / Draftable：默认显示风险摘要和可决策信息；hunk、hash、rule_id、locator 作为可下钻证据，避免用户面对另一堵 Diff 墙。

建立“新事实使旧批准失效”规则

借鉴 GitLab 和 Terraform：结果 hash、源文件或相关 hunk 变化后，旧人工决定不能静默沿用；必须明确 stale 并要求重审受影响任务。

用对照实验验证是否真省时间

同一文档、同一批注、同一 Agent 输出，让用户分别用 git diff/revdiff、Redline、DocGate 验收；记录耗时、漏检、错误接受和返工轮数。

现在不要做

批注 UI

Plannotator、Redline、Commentary、md-redline 已密集覆盖；继续自研只会进入同质化。

现在不要做

Word / PDF 全格式

Pandoc、MarkItDown、Docling、MinerU 可作为未来 adapter；P0 先把 Markdown 证据模型跑通。

持续监控

Redline + MD Feedback

一旦它们补上独立磁盘验证、未声明变更和返工门槛，DocGate 的窗口会显著收窄。
